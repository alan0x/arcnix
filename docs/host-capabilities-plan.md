# 主机能力接口演进计划

Arcnix 的 App 通过 Worker 访问主机能力。一个 App 可以使用多个接口，多个 App 可以共享同一个接口。客户端的操作系统决定本机实现，SSH 会话的目标环境决定远端实现。

## 接口边界

| 能力 | 现有数据和操作 | 演进方向 |
| --- | --- | --- |
| 资源采样 | `ResourceSnapshot`、`ResourceUsage`、指标历史 | 共享字节、百分比、采样时钟与缺失字段语义。平台实现负责采集，公共逻辑负责趋势。 |
| 文件与文档 | `FileEntry`、文档快照、版本校验、SFTP | 文件读取与写入分别提供。路径、命名空间和权限由各实现处理。Files、Code 和查看器共用读取接口。 |
| 主机清单 | 磁盘、网卡配置、进程和监听端口 | 资源用量和硬件清单分别提供。结果区分空清单、能力缺失和权限拒绝。 |
| 服务与日志 | 服务列表、详情、日志查询与操作计划 | 查询、控制和日志来源分别提供。服务控制仍须经过原有任务审核和授权。 |
| 软件与系统设置 | 包管理环境、安装计划、Docker 操作、时区 | 按账号和工具可用性提供读写能力。分清应用偏好写入与系统配置写入。 |
| 终端与后台任务 | SSH PTY、WSL 终端、systemd 任务 | 交互终端与结构化能力相互独立。后台任务保留原有作业生命周期和授权。 |

SSH 执行、SFTP 和本机调用属于传输与执行层。SSH 环境探测在主机信任与认证之后进行，结果随连接失效。系统类型、命令环境、SFTP 和应用能力分别记录。能力状态区分待探测、可用、不支持、权限拒绝和暂时失败。缺少某项能力时，其他可用功能继续工作。

## 阶段与验收

1. **本机 Monitor。** 引入资源读取接口，接入现有 Linux、Windows 和新 Darwin 采集器，按本机会话能力开放应用入口。macOS 只读与读写使用相同采样器，覆盖 CPU、内存、磁盘空间和网卡流量。验收包括真实两次采样、应用入口、只读限制和现有指标回归。
2. **远端资源与环境。** 在 SSH 登录后按能力探测执行环境。保留 Linux 采样，按实际环境逐步接入 Darwin 和原生 Windows。保留仅 SFTP 以及仅 SSH 执行的使用路径。验收包括探测响应错误、连接切换、真实 Linux 与 macOS SSH，以及 Windows OpenSSH 的 cmd 和 PowerShell 环境。
3. **文件与文档。** 先迁移 Files、Code 和 PDF 的目录读取、新建、带上限读取、文档打开和保存。再迁移 Files 的移动、删除、传输和提权访问，以及媒体的范围读取。验收覆盖版本冲突、编码、只读限制、操作取消和连接切换。Windows SSH 的驱动器路径单独用原生 SFTP 验证。
4. **主机清单、日志与服务。** 独立定义进程与端口、磁盘设备、网卡地址、日志查询、服务查询和服务控制能力。先迁移现有 Linux 实现，再接入 macOS 或 Windows 已确认可用的能力。验收覆盖空结果、命令缺失、权限拒绝和部分支持。清单验证完成前，Monitor 的基础指标可单独使用。
5. **软件、设置与后台任务。** 拆分包清单与安装、容器查询与操作、系统设置读取与写入、终端及远端任务。先接入现有实现，再按目标环境提供新实现。验收覆盖原有操作审核、权限延续、任务取消、重试和记录恢复。安装或写入操作各自按平台和账号能力启用。

## 进度

- 第一阶段已实现并在 macOS 实机验证。只读桌面可从 Dock 打开 Monitor，两次采样后显示 CPU、内存和网络速率，磁盘页可查看挂载卷。Linux 和 Windows 本机通过同一接口继续使用原有采集器。
- 第二阶段的基础指标已接线。SSH 首次采样时探测远端系统，连接内复用探测结果。Linux 已在原生 OpenSSH 上验证真实采样，也通过了无需 SFTP 的回环测试。Darwin 通过本机临时启动的原生 OpenSSH 实例验证了密钥认证、系统识别和两次真实采样。Windows 采样覆盖 PowerShell 脚本解析和模拟记录转换，原生 Windows OpenSSH 的 cmd 和 PowerShell 登录环境仍需实机验收。
- 第三阶段已迁移现有文件操作。Files、Code 和查看器共用目录枚举、新建、限量读取和文档读写接口。重命名、移动、删除、回收站、权限修改、上传下载、媒体读取和文本分页分别接入对应能力。原生 Linux OpenSSH 与 sudo 验证了已审核文档、分页、复制和删除的授权及路径复核。回环 SFTP 覆盖取消、版本冲突、部分进度和并发传输。原生 Windows OpenSSH 的驱动器路径仍待实机验收。
- 第四阶段已为 Linux、macOS 和 Windows SSH 会话接入磁盘、网卡地址、进程、监听端口、系统日志和服务接口。macOS 使用 Unified Log 和 launchd 系统域，Windows 使用 System 与 Application Event Log 及服务控制管理器。Linux 服务变更继续走后台任务。macOS 和 Windows 服务变更通过当前 SSH 会话审核并复核服务状态后执行。
- macOS 的停止请求发送 SIGTERM，launchd 可按策略重新启动服务。系统域变更需要 root 或为该操作配置的非交互 sudo。Windows 服务变更由连接账号持有的服务权限决定。macOS 和 Windows 端口清单只读。
- 已在原生 macOS OpenSSH 验证清单、日志、服务查询和变更预览。Windows 验证覆盖编码命令、模拟 Windows API、返回解析、过期审核拒绝，以及界面确认后刷新服务状态。Windows 原生 OpenSSH 验收和 macOS 提权变更实操仍待完成。
- 第五阶段已迁移包环境、清单、搜索、安装预览、Docker 查询与操作、Compose 查询、系统时钟与时区、桌面偏好、SSH PTY 和后台任务。包安装继续沿用 APT 审核与任务提交。任务提交、结果观察、历史读取和停止计划各自独立，保留 systemd 任务记录、操作锁和取消规则。
- 时区由各 SSH 平台读取和应用，并回读确认结果。macOS 通过已安装的时区数据和 systemsetup，Windows 使用系统时区 ID。桌面偏好使用独立存储接口。macOS Docker 使用连接账号可以访问的本机套接字，Compose 工作流继续使用 Linux 实现。
- 原生 macOS OpenSSH 已验证时区、服务器时钟和 Docker 清单。Windows 回环测试覆盖选择时区后的回读与时钟偏移。后台任务回环测试验证了提交、操作锁、断开后重新观察和读取历史记录。
- macOS 接入 Homebrew formulae，Windows 接入 WinGet 社区源。已安装清单和仓库搜索通过软件包接口提供。安装、升级、卸载和刷新索引通过 SSH 终端执行，用户审核后按 Enter。Windows 连接账号需要能访问 WinGet、PowerShell 7 及 `Microsoft.WinGet.Client` 模块。
- Windows Docker 通过目标主机本地命名管道读取容器、镜像、卷、资源和日志，并执行已确认的容器操作。访问取决于 SSH 账号的 Docker 权限。Windows 远端桌面偏好写入该账号的 `%LOCALAPPDATA%\Arcnix\desktop.v1`，沿用三方合并，按版本校验并原子替换文件。
- macOS 本机通过临时原生 OpenSSH 验证 Homebrew 清单与搜索。Windows 回环 SSH 覆盖 WinGet、Docker 和桌面偏好传输。
- macOS 和 Windows 的持久任务首个操作是远端文件 SHA-256 校验，可选择对比预期值。从「任务 → 服务器记录」提交并查看状态、日志和历史，活动任务可审核后停止。服务器以 SSH 账号权限执行，任务 ID 绑定到原始请求，重复提交不会重复运行。任务结束前若丢失运行实例，记录显示「已中断」。
- macOS 通过当前账号可用且允许注册的 launchd 登录域启动一次性任务。Windows 使用 Task Scheduler 的有限权限 S4U 登录，账号需要能注册和启动该任务，校验输入为服务器上的本地常规文件。任务没有计划触发器，主机重启后保留记录，由用户决定是否重跑。
- 原生 macOS OpenSSH 已在有 GUI 登录域的账号上验证校验成功、不匹配、断开重连、重复提交、历史与停止。Windows 已通过回环 SSH 和使用调度器替身的 PowerShell 脚本测试。Windows 原生 OpenSSH 与 Task Scheduler 联合验收、macOS 无 GUI 登录域以及 macOS 提权时区写入仍待实机验证。
