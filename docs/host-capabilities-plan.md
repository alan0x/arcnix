# 主机能力接口演进计划

Arcnix 的 App 通过 Worker 访问主机能力。一个 App 可以使用多个接口，多个 App 可以共享同一个接口。客户端的操作系统决定本机实现，SSH 会话的目标环境决定远端实现。

## 接口边界

| 能力 | 现有数据和操作 | 演进方向 |
| --- | --- | --- |
| 资源采样 | `ResourceSnapshot`、`ResourceUsage`、指标历史 | 共享字节、百分比、采样时钟与缺失字段语义。平台实现负责采集，公共逻辑负责趋势。 |
| 文件与文档 | `FileEntry`、文档快照、版本校验、SFTP | 文件读取与写入分别提供。路径、命名空间和权限由各实现处理。Files、Code 和查看器共用读取接口。 |
| 主机清单 | 磁盘、网卡配置、进程和监听端口 | 资源用量和硬件清单分别提供。结果区分空清单、能力缺失和权限拒绝。 |
| 服务与日志 | 服务列表、详情、日志查询与操作计划 | 查询、控制和日志来源分别提供。服务控制仍须经过原有任务审核和授权。 |
| 软件与系统设置 | 包管理环境、安装计划、Docker 操作、时区 | 按账号和工具可用性提供读写能力。分清应用偏好写入与系统配置写入。 |
| 终端与后台任务 | SSH PTY、WSL 终端、systemd 任务 | 交互终端与结构化能力相互独立。后台任务保留原有作业生命周期和授权。 |

SSH 执行、SFTP 和本机调用属于传输与执行层。SSH 环境探测在主机信任与认证之后进行，结果随连接失效。系统类型、命令环境、SFTP 和应用能力分别记录。能力状态区分待探测、可用、不支持、权限拒绝和暂时失败。缺少某项能力时，其他可用功能继续工作。

## 阶段与验收

1. **本机 Monitor。** 引入资源读取接口，接入现有 Linux、Windows 和新 Darwin 采集器，按本机会话能力开放应用入口。macOS 只读与读写使用相同采样器，覆盖 CPU、内存、磁盘空间和网卡流量。验收包括真实两次采样、应用入口、只读限制和现有指标回归。
2. **远端资源与环境。** 在 SSH 登录后按能力探测执行环境。保留 Linux 采样，按实际环境逐步接入 Darwin 和原生 Windows。保留仅 SFTP 以及仅 SSH 执行的使用路径。验收包括探测响应错误、连接切换、真实 Linux 与 macOS SSH，以及 Windows OpenSSH 的 cmd 和 PowerShell 环境。
3. **文件与文档。** 先迁移 Files、Code 和 PDF 的目录读取、新建、带上限读取、文档打开和保存。再迁移 Files 的移动、删除、传输和提权访问，以及媒体的范围读取。验收覆盖版本冲突、编码、只读限制、操作取消和连接切换。Windows SSH 的驱动器路径单独用原生 SFTP 验证。
4. **主机清单、日志与服务。** 独立定义进程与端口、磁盘设备、网卡地址、日志查询、服务查询和服务控制能力。先迁移现有 Linux 实现，再接入 macOS 或 Windows 已确认可用的能力。验收覆盖空结果、命令缺失、权限拒绝和部分支持。清单验证完成前，Monitor 的基础指标可单独使用。
5. **软件、设置与后台任务。** 拆分包清单与安装、容器查询与操作、系统设置读取与写入、终端及远端任务。先接入现有实现，再按目标环境提供新实现。验收覆盖原有操作审核、权限延续、任务取消、重试和记录恢复。安装或写入操作各自按平台和账号能力启用。

## 进度

- 第一阶段已实现并在 macOS 实机验证。只读桌面可从 Dock 打开 Monitor，两次采样后显示 CPU、内存和网络速率，磁盘页可查看挂载卷。Linux 和 Windows 本机通过同一接口继续使用原有采集器。
- 第二阶段的基础指标已接线。SSH 首次采样时探测远端系统，连接内复用探测结果。Linux 路径经过无需 SFTP 的回环 SSH 测试，Darwin 通过本机临时启动的原生 OpenSSH 实例验证了密钥认证、系统识别和两次真实采样。Windows 采样覆盖 PowerShell 脚本解析和模拟记录转换，原生 Windows OpenSSH 的 cmd 和 PowerShell 登录环境仍需实机验收。
- 第三阶段已迁移第一组文件能力。Files 和 Code 共用目录枚举，Code 通过独立接口创建文件或目录，PDF 本机与 SSH 共用带大小限制的文件读取接口，普通文本读取和带版本校验的保存分别接入独立接口。回环 SFTP 验证了保存时保留文件编码和权限，并拒绝取消或过期的写入。移动、删除、传输、提权和范围读取仍待迁移。
- 第四和第五阶段待实施。
