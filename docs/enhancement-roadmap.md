# 运维增强进度与边界

本文件延续本次改进报告，并记录用户后续明确的边界：客户端是辅助运维工具，允许随时关闭和升级。本次不做要求客户端常驻的定时调度、持续监控和自动维护。长任务交由服务器工具持有执行过程、日志和结果。

优先增强批量操作的可靠性、恢复能力和发行版适配，再增加更多操作入口。服务器端可以使用 systemd、restic、数据库原生客户端等现成工具；不为每项功能另建桌面后台执行器，也不要求安装 Arcnix 常驻 Agent。

## 执行归属与验收原则

| 操作类型 | 执行与保存位置 | 客户端关闭后的行为 |
| --- | --- | --- |
| 查询资源、日志、列表和配置差异 | 客户端按需发起 SSH 查询 | 查询停止，下次打开重新获取；旧数据标明时间 |
| 安装、导出、备份、恢复和配置发布 | 服务器接收完整请求后执行，服务器保存日志和结果 | 已接收任务独立完成；重新连接只查询原任务 |
| 尚未提交或提交确认丢失 | 分别显示待提交或结果未知 | 不宣称已经运行，不自动重复提交 |
| 定时备份、持续监控、自动处置 | 本次排除 | 后续若做，计划、状态和执行必须归服务器工具持有 |

多目标操作区分提交并发与运行并发。当前并发数限制预检查／提交连接；服务器接收后释放名额，因此运行中的任务可能更多。需要“第一台成功后再执行下一台”的灰度发布时，应另做服务器端编排与持久状态，不能让桌面轮询成为下一步能否开始的前提。

客户端退出独立性不等于服务器重启恢复能力。长任务是否支持服务器重启、工具升级、异常终止和重试，需要逐类明确；未知结果先核验，不能简单归为失败后重跑。通用脚本也不承诺幂等、模拟和回滚。

- 已停止且可证明的残留可独立审核并提交服务器私有导出，源文件保留；选择完成导出后，另行审核并完整校验导出字节与元数据，再移除源暂存文件。中断后保留余项，新任务可重新核验后处理；不恢复已删除数据、业务原路径或原权限，不自动续跑。两类任务均支持多服务器且不依赖客户端常驻。

- 已完成且停止的导出可从关联报告或独立导出库存下载为 ZIP，包含数据、原始元数据及审计依据，不要求 SFTP，也不依赖原暂存区仍存在。传输核对字节及最终回执后才发布本地文件；取消或客户端关闭保留服务器副本，不自动重试，不覆盖本地同名文件。

- 账户任务支持跨服务器、跨页选择最多 100 个活动任务，重新认证并只读核验原账户、记录、systemd 调用及 cgroup 身份，再显式提交已通过核验的范围。停止批次独立于普通运行队列，不被目标持有的运维锁阻塞；未提交目标可取消，已接收控制任务由服务器继续完成。
- 停止请求不等于停止完成：服务器确认原进程和整个原 cgroup 均已退出后逐项报告，身份变化、拒绝或无法确认单独保留；同名替代运行不沿用旧计划。结果可从最近批次或独立服务器记录查询，缺失或不匹配报告不因退出 0 而成功；说明置于 `?`，保留部分变更风险提示。

- 诊断结果可从最近批次或独立服务器任务日志导出离线 HTML。先固定保存快照、选择服务器并预览，默认排除检查明细及全部执行脚本；未知、范围缺失或不匹配不会成为已核验结论，保存不覆盖已有文件，不产生服务器请求。
- 新采集器保存系统、内核／架构及相关工具的实际版本输出，旧报告明确显示未记录；界面置于 `?`，分享报告一并保留采样、接收及导出时间。支持中文与英文，HTML 不含脚本或外部资源。

- 故障服务诊断可直接打开独立日志弹窗，从已保存的完整报告提取服务名，按诊断采样前后各 15 分钟或最近时段有限读取。原工作区保持连接，管理员读取需明确选择；说明收在 `?`。支持独立服务器记录，不依赖本地历史或客户端常驻。
- TCP 端口发现及独立记录可按需查看当前网络命名空间的监听地址、可见 PID 与 cgroup 服务线索；预填原端口，独立连接和可选管理员读取，核对 PID 起始时间／描述符并标记覆盖限制。无进程明细不判为空闲，cgroup 不替代服务状态；失败保留原快照，不自动停止进程或变更服务。

## 常见运维场景与便捷操作

下表为具体增强方向，沿用“选择目标 → 预检查 → 审核计划 → 服务器执行 → 查询结果”的流程，避免堆放没有结果核验的命令按钮。

| 场景 | 便捷操作 | 必须具备的结果与限制 |
| --- | --- | --- |
| 新服务器初始化 | 选择经过适配的工具安装模板，填写版本、目录和服务参数，批量预检查 | 显示包变更、配置影响和权限；分别检查安装完成、服务状态与应用健康。保留现有数据，升级与全新安装分别处理 |
| 磁盘或 inode 用尽 | 已可诊断后统计目录及排查已删除文件占用；继续完善日志／容器空间和清理候选 | 已删除文件按设备／inode 去重，显示可见持有者及读取限制；不自动终止进程或将观察块数视为可释放空间。清理先核对精确对象，不默认删除数据库目录、容器卷或未核对的备份，也不启动周期清理 |
| 服务启动失败 | 已提供故障服务日志、配置校验及 TCP 监听／进程排查，继续关联近期变更 | 服务线索与实际状态分开，重启与重载仍是单独确认的操作；修复后重新检查，不能用命令退出码替代应用健康 |
| 数据误删或错误发布 | 选择快照／版本，预览恢复内容，默认恢复到新目录或新库 | 保留当前数据和恢复依据；校验恢复内容，明确应用接管是后续步骤。配置恢复可复用现有发布流程 |
| TLS 证书将到期 | 已可检查本地 PEM 及对外实际直接 TLS；后续按需调用已有 ACME 工具并核验续期 | 当前从所选服务器核对链、域名／IP、有效期及到期阈值；实际网络、时钟及 CA 库属于该服务器视角。证书密钥和续期状态留在服务器，不增加后台续期调度 |
| 系统补丁与维护 | 展示包更新计划、服务影响和是否需要重启，按目标生成维护记录 | 长安装由服务器执行；重启另行确认，重连后核验结果。跨服务器分阶段维护需要服务器端编排后再做 |
| SSH／防火墙变更 | 未来提供专用预检查、备份及服务器端限时恢复方案 | 当前不提供通用一键修改；必须能在客户端断开后自行恢复，并验证新的连接入口，不能只依赖原 SSH 会话仍存活 |

服务器独立执行可基于现成的 [systemd transient service](https://www.freedesktop.org/software/systemd/man/latest/systemd-run.html)；快照文件浏览可基于 [restic ls](https://restic.readthedocs.io/en/stable/045_working_with_repos.html#listing-files-in-a-snapshot)。应用发布需采用各应用自己的校验与生效机制，例如 [Nginx 配置重载](https://nginx.org/en/docs/control.html#reconfiguration)，再增加独立的应用健康检查。
